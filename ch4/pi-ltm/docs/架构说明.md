# pi-okf-memory 架构说明

## 分层

| 层 | 模块 | 职责 | 依赖 |
|---|---|---|---|
| L0 | `pi-okf`（npm CLI） | OKF v0.2 解析、校验、index/log 生成 | — |
| L1 | `ltm_core/okf_cli.py` | 唯一 OKF 边界：init/validate/index/capture/inspect | pi-okf |
| L1 | `ltm_core/concept.py` | frontmatter 文本发射、原子写、正文切分 | 标准库 |
| L2 | `ltm_core/project.py` | realpath 归一、projectId、WSL/Windows 映射、路径白名单 | 标准库 |
| L2 | `ltm_core/lock.py` | O_EXCL 锁文件、退避重试、陈旧抢占 | 标准库 |
| L2 | `ltm_core/cache.py` | JSON 索引缓存，mtime+size 增量校验 | 标准库 |
| L3 | `ltm_core/memory.py` | write / read / update / delete / warm / status | L1+L2 |
| L4 | `src/extension.ts` | 4 个工具 + `/memory` + `session_start` 预热与注入 | L3 |
| L5 | `ops/*.py` | 导出与全量校验 | L3 |

依赖方向单向：`extension.ts → cli.py → memory.py → okf_cli.py → pi-okf`。

## 存储布局

```
<project>/.pi/ltm/
├── okf/                              OKF v0.2 bundle（唯一真源）
│   ├── index.md                      pi-okf index --write 维护
│   ├── log.md                        pi-okf capture 维护
│   ├── <slug>-<id8>.md               概念文件（bundle 根目录）
│   └── trash/*.md.orig               软删除归档，不被概念扫描收录
├── .index/memory-index.json          可重建缓存
├── ltm.config.json
└── .lock
```

全局作用域为 `~/.pi/ltm/`，结构相同。

## 概念文档形态

```yaml
---
type: "Memory"
title: "会话测试入口"
description: "..."
generated:
  by: "process:pi-okf-memory"
  at: "2026-11-18T09:00:00.000Z"
id: "mem_1a2b3c4d"
key: "session-test-entry"
project: "C:/projet/homework/ch4/pi-ltm"
projectId: "abc123def456"
sources:
  - resource: "tests/test_session.py"
tags: ["memory"]
status: "stable"
revision: 1
---
# Content
...
# Citations
[1] tests/test_session.py
```

- 概念文件位于 **bundle 根目录**：`pi-okf index --write` 只索引当前目录的概念，放入子目录会导致根索引为空并触发硬错误。
- `sources` 必须是 `{resource: string}` 对象数组，否则触发 v0.2 警告。
- `status` 使用 `stable` / `deprecated`（`active` 会触发警告）。
- `generated.by` 使用 `process:` 参与者前缀。

## 写入时序

1. 归一化 project → 路径白名单校验（越界 `PATH_FORBIDDEN`）
2. 取锁（O_EXCL + 退避 + 陈旧抢占）
3. `pi-okf init` 幂等补齐 bundle，并清理示例概念
4. 缓存判冲突：同 project+key 已存在 → `CONFLICT`（附 id）
5. 发射 frontmatter → 临时文件 → fsync → `os.replace`
6. `pi-okf validate --json` 门禁；`rc=1` 回滚并返回 `OKF_INVALID`
7. `pi-okf index --write` + `pi-okf capture`
8. 增量刷新缓存，返回绝对路径

## 错误码

`INVALID_ARGS` / `CONFLICT` / `NOT_FOUND` / `AMBIGUOUS` / `OKF_INVALID` / `PATH_FORBIDDEN` / `LOCK_TIMEOUT` / `INTERNAL`。

## 扩展点

- `kind` 词表：`test` / `decision` / `preference` / `fact`
- `scope`：预留 `workspace` 聚合检索
- `retrieval`：当前 key + 子串，预留 BM25/向量接口
- `okf_cli.py` 单点替换，隔离 `pi-okf` 升级
- 事件广播 `ltm:written` / `ltm:updated`
